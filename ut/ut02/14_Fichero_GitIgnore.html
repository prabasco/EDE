    El archivo .gitignore en Git¶

    ¿Qué es .gitignore?¶

    El archivo .gitignore permite indicar a Git qué archivos y carpetas debe ignorar al detectar archivos nuevos en un repositorio.

    Se utiliza para evitar que determinados archivos se incorporen al control de versiones, como por ejemplo:

    • Archivos temporales generados por el sistema operativo.
    • Archivos compilados (.class, .exe, etc.).
    • Carpetas generadas automáticamente por los entornos de desarrollo.
    • Archivos de configuración local que son diferentes en cada equipo.
    • Archivos con información sensible, como contraseñas o claves de acceso.

    Importante

    .gitignore solo afecta a los archivos que Git todavía no está siguiendo (untracked).

    Si un archivo ya está registrado en el repositorio, añadirlo a .gitignore no hará que Git deje de seguirlo automáticamente.

    Crear un archivo .gitignore¶

    El archivo .gitignore se crea normalmente en la raíz del repositorio, al mismo nivel que la carpeta .git.

    Ejemplo de estructura:

    MiProyecto/
│
├── .git/
├── .gitignore
├── README.md
├── src/
│   └── Main.java
├── bin/
│   └── Main.class
└── logs/
    └── errores.log

    En Windows, desde la terminal de VS Code o PowerShell, podemos crearlo mediante:

    New-Item .gitignore -ItemType File

    Desde CMD:

    type nul > .gitignore

    También podemos crearlo directamente desde el explorador de archivos de VS Code.

    Sintaxis del archivo .gitignore¶

    Dentro del archivo .gitignore escribimos los nombres o patrones de los archivos y carpetas que queremos ignorar.

    Patrón Significado
    archivo.txt Ignora los archivos con ese nombre
    *.log Ignora todos los archivos con extensión .log
    *.class Ignora los archivos compilados de Java
    bin/ Ignora las carpetas llamadas bin y su contenido
    /temp/ Ignora la carpeta temp situada en la raíz
    !importante.log Excepción: permite no ignorar ese archivo si las demás reglas lo permiten
    # comentario Añade un comentario
    config?.txt Ignora archivos como config1.txt o configA.txt

    Uso de comodines

    • * representa cero o más caracteres dentro de un nombre o componente de ruta.
    • ? representa exactamente un carácter.
    • ** permite definir patrones que abarcan varios niveles de directorios.
    • ! permite establecer excepciones a las reglas de exclusión.

    Ejemplo de .gitignore para un proyecto Java¶

    # Archivos compilados
*.class
*.jar

# Carpetas de compilación
bin/
build/
target/
out/

# Archivos temporales
*.tmp
*.log

# Configuración de IntelliJ IDEA
.idea/
*.iml

# Configuración local
.env

    Con esta configuración, Git ignorará los archivos y directorios indicados siempre que todavía no estén bajo seguimiento.

    Ejemplo práctico de funcionamiento¶

    Vamos a crear un repositorio con varios archivos y comprobar cómo funciona .gitignore.

    Paso 1. Crear el repositorio¶

    mkdir ProyectoGit
cd ProyectoGit
git init

    Paso 2. Crear archivos y carpetas¶

    Creamos la siguiente estructura:

    ProyectoGit/
│
├── .gitignore
├── README.md
├── Main.java
├── Main.class
├── errores.log
└── bin/
    └── Programa.class

    Paso 3. Configurar .gitignore¶

    Editamos el archivo .gitignore e introducimos:

    # Ignorar archivos compilados
*.class

# Ignorar archivos de registro
*.log

# Ignorar carpeta bin
bin/

    Paso 4. Consultar el estado del repositorio¶

    Ejecutamos:

    git status

    Git mostrará como archivos sin seguimiento:

    Untracked files:
    .gitignore
    README.md
    Main.java

    Los archivos Main.class, errores.log y la carpeta bin/ no aparecerán porque coinciden con las reglas de .gitignore.

    Paso 5. Añadir los archivos al área de preparación¶

    git add .

    Aunque utilicemos git add ., Git no añadirá los archivos ignorados.

    Podemos comprobarlo con:

    git status

    Resultado:

    Changes to be committed:
    new file:   .gitignore
    new file:   Main.java
    new file:   README.md

    Paso 6. Realizar el commit¶

    git commit -m "Primer commit con gitignore"

    Solo se almacenarán en el repositorio los archivos que no estén ignorados.

    Recomendación

    El propio archivo .gitignore debe añadirse al repositorio mediante un commit, para que todos los desarrolladores compartan las mismas reglas de exclusión.

    ¿Qué ocurre si un archivo ya está siendo seguido por Git?¶

    Supongamos que hemos añadido previamente errores.log al repositorio:

    git add errores.log
git commit -m "Añadir archivo de errores"

    Posteriormente añadimos esta regla a .gitignore:

    *.log

    Git continuará siguiendo errores.log, porque ya formaba parte del repositorio.

    Para dejar de seguirlo sin eliminarlo de nuestro ordenador, ejecutamos:

    git rm --cached errores.log

    Después confirmamos el cambio:

    git add .gitignore
git commit -m "Dejar de controlar archivos log"

    A partir de ese momento, errores.log permanecerá en nuestro directorio de trabajo, pero Git lo ignorará.

    Atención

    • git rm archivo elimina el archivo del índice y del directorio de trabajo.
    • git rm --cached archivo lo elimina únicamente del índice de Git, conservándolo en el directorio de trabajo.

    El archivo seguirá existiendo en los commits anteriores del historial.

    Comprobar si un archivo está siendo ignorado¶

    Podemos utilizar el comando:

    git check-ignore -v nombreArchivo

    Por ejemplo:

    git check-ignore -v errores.log

    Resultado:

    .gitignore:5:*.log    errores.log

    Este resultado indica que el archivo está siendo ignorado por la regla *.log, situada en la línea 5 del archivo .gitignore.

    Para comprobar archivos ya seguidos por Git, podemos añadir la opción --no-index:

    git check-ignore --no-index -v errores.log

    Plantillas de .gitignore¶

    No es necesario escribir todas las reglas manualmente. GitHub dispone de plantillas preparadas para diferentes lenguajes de programación, sistemas operativos y entornos de desarrollo.

    Podemos consultar las plantillas oficiales en:

    Repositorio de plantillas gitignore de GitHub

    Al crear un repositorio en GitHub también podemos seleccionar una plantilla .gitignore apropiada para nuestro proyecto.

    Resumen de comandos¶

    Comando Descripción
    git status Muestra los archivos nuevos, modificados y preparados
    git add . Añade los archivos no ignorados al área de preparación
    git check-ignore -v archivo Comprueba qué regla ignora un archivo no seguido
    git rm --cached archivo Deja de seguir un archivo sin borrarlo del disco
    git ls-files Muestra los archivos que Git está siguiendo
    git status --ignored Muestra también los archivos ignorados

    Recuerda

    • .gitignore indica qué archivos no deben incorporarse al seguimiento de Git.
    • No elimina archivos del ordenador.
    • No afecta automáticamente a los archivos que ya están siendo seguidos.
    • Debe guardarse en el repositorio para compartir las reglas con el equipo.
    • No elimina información sensible del historial de Git si ya se ha confirmado anteriormente.
