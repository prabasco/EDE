    Instalación de Git¶

    La instalación de Git es muy sencilla. En la mayoría de los casos consiste en descargar e instalar el programa correspondiente al sistema operativo.

    Antes de empezar

    El instalador de Git debe descargarse desde la página oficial de Git. El procedimiento de instalación dependerá del sistema operativo utilizado.

    Instalar Git en Linux¶

    En muchas distribuciones Linux, Git ya se encuentra instalado. Para comprobar si Git está disponible y conocer su versión ejecutamos:

    git --version

    Si está instalado, aparecerá un resultado similar a:

    git version 2.51.0

    Si no está instalado, puede instalarse utilizando el gestor de paquetes de la distribución. Por ejemplo, en Ubuntu/Debian:

    sudo apt update
sudo apt install git

    Instalar Git en Windows¶

    En Windows, Git se instala mediante un instalador que puede descargarse desde la página oficial de Git.

    Durante la instalación podemos instalar también Git Bash, un terminal basado en Bash que permite utilizar muchos de los comandos habituales de Linux.

    Una vez terminada la instalación podemos comprobarla mediante:

    git --version

    Git Bash

    Git Bash proporciona en Windows un entorno de terminal similar al utilizado en Linux. Resulta especialmente útil para trabajar con Git y otras herramientas habituales de desarrollo.

    Instalar Git en macOS¶

    Git puede instalarse utilizando el instalador disponible en la página oficial. Algunas versiones de macOS también pueden tener Git disponible previamente.

    Otra posibilidad es instalarlo mediante Homebrew:

    brew install git

    Después podemos comprobar la instalación:

    git --version

    Configuración inicial¶

    Después de instalar Git es recomendable realizar una configuración inicial.

    La opción --global indica que la configuración se aplicará a todos los repositorios Git del usuario.

    Nombre y correo electrónico¶

    Git utiliza el nombre y el correo electrónico para identificar al autor de los commits.

    git config --global user.name "Tu nombre"
git config --global user.email "tu_email@example.com"

    Para comprobar los valores configurados:

    git config --global user.name
git config --global user.email

    Configurar el editor¶

    Git necesita un editor de texto para determinadas operaciones, como escribir mensajes de commit, realizar operaciones de rebase o resolver determinadas situaciones.

    Podemos configurar el editor que queremos utilizar.

    git config --global core.editor "code --wait"

    git config --global core.editor "idea --wait"

    git config --global core.editor "notepad"

    Para comprobar el editor configurado:

    git config --global core.editor

    Activar colores en la terminal¶

    Git puede utilizar colores para facilitar la interpretación de la información mostrada por comandos como git status, git branch o git log.

    Para activar automáticamente el coloreado:

    git config --global color.ui auto

    El valor auto indica que Git utilizará colores cuando la salida se muestre directamente en una terminal.

    Mostrar la versión original en los conflictos¶

    Cuando dos ramas modifican una misma parte de un archivo puede producirse un conflicto.

    Podemos configurar Git para que, además de mostrar las dos versiones en conflicto, muestre también la versión original común:

    git config --global merge.conflictstyle diff3

    Con diff3 podremos distinguir:

    Nuestra versión
      ↓
Versión original
      ↓
Versión de la otra rama

    Esto facilita la resolución de conflictos al permitir comparar cómo era originalmente el código y qué modificaciones se han realizado en cada rama.

    Configurar alias para el historial¶

    Git permite crear alias, es decir, comandos abreviados para ejecutar comandos más largos.

    Podemos crear un alias llamado lg para visualizar el historial de commits de una forma más compacta y gráfica:

    git config --global alias.lg "log --graph --abbrev-commit --decorate --format=format:'%C(bold blue)%h%C(reset) - %C(bold green)(%ar)%C(reset) %C(white)%s%C(reset) %C(dim white)- %an%C(reset)%C(bold yellow)%d%C(reset)'"

    A partir de ese momento podemos ejecutar:

    git lg

    En lugar de escribir todo el comando anterior.

    También podemos crear otro alias para mostrar el historial de todas las ramas:

    git config --global alias.lga "lg --all"

    Y utilizarlo mediante:

    git lga

    Alias

    Los alias no crean nuevos comandos internos de Git. Simplemente permiten asignar un nombre corto a otro comando o conjunto de opciones que utilizamos frecuentemente.

    Mostrar la configuración final¶

    Podemos consultar toda la configuración global mediante:

    git config --global --list

    El resultado será similar a:

    user.name=Tu nombre
user.email=tu_email@example.com
core.editor=code --wait
color.ui=auto
merge.conflictstyle=diff3
alias.lg=log --graph ...
alias.lga=lg --all

    También podemos conocer el archivo del que procede cada configuración:

    git config --list --show-origin

    Creación de un repositorio¶

    Para crear un repositorio Git desde cero podemos crear una carpeta para nuestro proyecto y situarnos dentro de ella desde el terminal.

    Por ejemplo:

    mkdir mi-proyecto
cd mi-proyecto

    Inicializamos el repositorio:

    git init

    Git crea dentro del directorio una carpeta oculta denominada:

    .git

    Esta carpeta contiene la información necesaria para gestionar el repositorio: configuración, referencias, commits, ramas y otros datos internos.

    No eliminar .git

    Si eliminamos la carpeta .git, los archivos del proyecto seguirán existiendo, pero la carpeta dejará de ser un repositorio Git y perderemos localmente su historial y configuración.

    Consultar el estado del repositorio¶

    Uno de los comandos más utilizados en Git es:

    git status

    Este comando permite conocer el estado actual del repositorio.

    Nos informa, entre otras cosas, de:

    • La rama actual.
    • Archivos nuevos que Git todavía no controla.
    • Archivos modificados.
    • Archivos eliminados.
    • Cambios añadidos al área de preparación (staging area).
    • Cambios pendientes de añadir.

    Utiliza git status frecuentemente

    git status no modifica ningún archivo ni el repositorio. Es un comando de consulta y puede ejecutarse siempre que necesitemos conocer el estado del proyecto.

    Añadir archivos al repositorio¶

    Para comenzar a controlar un archivo:

    git add nombreArchivo

    Por ejemplo:

    git add README.md

    Para añadir todos los cambios del directorio actual:

    git add .

    git add . frente a git add *

    Es preferible utilizar git add . para añadir todos los cambios del directorio actual. El comportamiento de * depende del shell y puede no incluir determinados archivos ocultos.

    También podemos añadir archivos concretos:

    git add LICENSE
git add README.md

    Realizar el primer commit¶

    Una vez preparados los archivos mediante git add, podemos guardar ese estado del proyecto en el historial:

    git commit -m "Versión inicial del proyecto"

    El flujo básico es:

    Directorio de trabajo
        │
        │ git add
        ▼
   Staging Area
        │
        │ git commit
        ▼
Repositorio Git local

    Consultar el historial¶

    Para mostrar el historial de commits:

    git log

    Cada commit mostrará información como:

    • Identificador del commit.
    • Autor.
    • Fecha.
    • Mensaje del commit.

    Para obtener una versión resumida:

    git log --oneline

    Si hemos configurado anteriormente nuestros alias, podemos utilizar:

    git lg

    Y para mostrar gráficamente todas las ramas:

    git lga

    Por tanto, disponemos de diferentes niveles de información:

    git log
git log --oneline
git lg
git lga

    Comandos básicos¶

    Comando Función
    git init Inicializa un repositorio Git
    git status Muestra el estado del repositorio
    git add archivo Añade un archivo al área de preparación
    git add . Añade todos los cambios
    git commit -m "mensaje" Crea un commit
    git log Muestra el historial
    git log --oneline Muestra el historial resumido
    git lg Muestra el historial gráfico mediante el alias configurado
    git lga Muestra gráficamente el historial de todas las ramas

    Información sobre las licencias

    Los repositorios públicos de GitHub se utilizan frecuentemente para compartir software de código abierto. Para indicar claramente bajo qué condiciones puede utilizarse, modificarse y distribuirse un proyecto es necesario elegir una licencia.

    La web Choose a License permite consultar las características de las principales licencias de software.

    Habitualmente la licencia se almacena en un archivo denominado LICENSE, LICENSE.txt o LICENSE.md situado en la raíz del repositorio.
