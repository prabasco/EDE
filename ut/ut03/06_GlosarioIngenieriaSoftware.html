    Glosario de ingeniería del software y equipos de desarrollo¶

    Este glosario reúne los conceptos fundamentales de la UT03 de Entornos de Desarrollo (1.º DAM). Complementa los apartados Ingeniería de software y Equipos de desarrollo de software. Cada término incluye una definición breve, un ejemplo cuando resulta útil y un enlace para ampliar información.

    Cómo estudiar este glosario

    Distingue entre fases (qué se hace), metodologías y marcos de trabajo (cómo se organiza), roles (quién participa) y tecnologías y herramientas (con qué se desarrolla).

    1. Fundamentos y ciclo de vida¶

    Término Significado y ejemplo Ampliación
    Software Programas, datos y recursos que permiten realizar tareas en un sistema informático. Wikipedia
    Ingeniería del software Aplicación de principios y métodos sistemáticos para diseñar, construir, probar y mantener software. Wikipedia
    Proyecto de software Trabajo temporal para obtener un producto o resultado; por ejemplo, crear una aplicación de biblioteca. Gestión de proyectos
    Ciclo de vida del software (SDLC) Etapas por las que pasa el software desde la idea hasta su retirada o sustitución. Wikipedia
    Requisito Necesidad o condición que el sistema debe satisfacer. Ejemplo: buscar libros por título. Análisis de requisitos
    Requisito funcional Describe qué debe hacer el sistema: registrar préstamos, iniciar sesión, etc. Requisito funcional
    Requisito no funcional Define propiedades de calidad o restricciones: seguridad, accesibilidad, rendimiento. Requisito no funcional
    Análisis Estudio del problema, usuarios y requisitos antes de diseñar la solución. Análisis de sistemas
    Diseño de software Definición de componentes, datos, interfaces y relaciones entre partes del sistema. Diseño de software
    Arquitectura de software Organización general del sistema y decisiones sobre sus componentes e interacciones. Wikipedia
    Implementación Conversión del diseño en código y componentes ejecutables. Implementación
    Pruebas de software Actividades para detectar defectos y comprobar que se cumplen los requisitos. Wikipedia
    Despliegue Publicación o instalación de una versión para que pueda utilizarse. Despliegue de software
    Mantenimiento Corrección de errores, adaptación y evolución de un sistema ya desarrollado. Wikipedia
    Documentación técnica Información que permite comprender, usar, mantener o ampliar un proyecto. Documentación de software
    Deuda técnica Coste futuro que generan decisiones técnicas que facilitan el trabajo inmediato pero complican su evolución. Wikipedia

    2. Modelos de desarrollo y agilidad¶

    Término Significado y ejemplo Ampliación
    Modelo en cascada Modelo secuencial: se avanza por etapas planificadas, como requisitos, diseño, construcción y pruebas. Wikipedia
    Modelo en V Relaciona actividades de especificación y diseño con niveles de verificación y validación. Wikipedia
    Desarrollo incremental El producto crece mediante entregas que añaden funcionalidades. Wikipedia
    Desarrollo iterativo Se repiten ciclos de trabajo para revisar y mejorar una solución. Wikipedia
    Metodologías ágiles Enfoques que favorecen la colaboración, las entregas frecuentes y la adaptación al cambio. Manifiesto Ágil
    Manifiesto Ágil Declaración de cuatro valores y doce principios que inspiran el desarrollo ágil. Texto oficial
    Scrum Marco de trabajo ligero para resolver problemas complejos mediante Sprints e inspección y adaptación. Scrum Guide (ES)
    Kanban Estrategia para visualizar el flujo de trabajo, limitar el trabajo en curso y mejorar el flujo. Kanban
    Tablero Kanban Panel visual con columnas como «Por hacer», «En progreso» y «Hecho». Atlassian
    WIP (Work in Progress) Trabajo en curso; limitarlo evita iniciar demasiadas tareas a la vez. Atlassian
    Mejora continua Revisión periódica del proceso para hacerlo más eficaz y fiable. Wikipedia
    DevOps Prácticas y cultura que acercan desarrollo y operaciones para entregar software con mayor fiabilidad. AWS
    Integración continua (CI) Integrar cambios con frecuencia y ejecutar verificaciones automáticas. GitHub Docs
    Entrega continua (CD) Mantener el software preparado para publicarse mediante procesos automatizados. Wikipedia
    Despliegue continuo Publicar automáticamente en producción los cambios que superan los controles establecidos. Wikipedia

    3. Scrum: responsabilidades, artefactos y eventos¶

    Terminología de Scrum

    La Guía Scrum 2020 habla de tres responsabilidades (Product Owner, Scrum Master y Developers), tres artefactos (Product Backlog, Sprint Backlog e Increment) y cinco eventos (Sprint, Sprint Planning, Daily Scrum, Sprint Review y Sprint Retrospective). «Project Manager» y «Tech Lead» no son responsabilidades definidas por Scrum.

    Término Significado y ejemplo Ampliación
    Scrum Team Equipo pequeño formado por Product Owner, Scrum Master y Developers. Guía Scrum
    Product Owner Responsable de maximizar el valor del producto y de gestionar eficazmente el Product Backlog. Guía Scrum
    Scrum Master Responsable de establecer Scrum y mejorar la eficacia del Scrum Team. Guía Scrum
    Developers Personas del Scrum Team que crean un incremento utilizable cada Sprint; pueden diseñar, programar o probar. Guía Scrum
    Stakeholder Persona o grupo interesado o afectado por el producto: cliente, usuarios, dirección, etc. Wikipedia
    Product Backlog Lista ordenada y evolutiva de lo necesario para mejorar el producto. Guía Scrum
    Product Goal Objetivo a largo plazo del producto; compromiso asociado al Product Backlog. Guía Scrum
    Sprint Periodo de duración fija de un mes o menos en el que se crea valor. Guía Scrum
    Sprint Planning Evento que establece por qué es valioso el Sprint, qué se hará y cómo se abordará. Guía Scrum
    Sprint Goal Objetivo único del Sprint; compromiso del Sprint Backlog. Guía Scrum
    Sprint Backlog Sprint Goal, elementos seleccionados del Product Backlog y plan para entregarlos. Guía Scrum
    Daily Scrum Evento de 15 minutos para inspeccionar el progreso hacia el Sprint Goal y adaptar el plan. Guía Scrum
    Incremento (Increment) Resultado utilizable que acerca el producto al Product Goal. Guía Scrum
    Definition of Done (DoD) Descripción formal del estado de calidad exigido a un incremento. Guía Scrum
    Sprint Review Evento para inspeccionar el resultado del Sprint con los interesados y decidir adaptaciones futuras. Guía Scrum
    Sprint Retrospective Evento para analizar cómo se trabajó y planificar mejoras de calidad y eficacia. Guía Scrum
    Historia de usuario Descripción breve de una necesidad desde el punto de vista del usuario: «Como lector quiero buscar libros por título para encontrarlos». Atlassian
    Criterios de aceptación Condiciones verificables que indican cuándo una historia cumple lo esperado. Atlassian
    Refinamiento del backlog Actividad continua de aclarar y descomponer elementos del Product Backlog. No es un evento formal de Scrum. Guía Scrum

    4. Personas y especializaciones del equipo¶

    Término Significado y ejemplo Ampliación
    Project Manager Profesional que coordina planificación, presupuesto, riesgos y seguimiento del proyecto. Wikipedia
    Business Analyst Analista de negocio que transforma necesidades de usuarios y organización en requisitos. IIBA
    Front-end Parte de la aplicación con la que interactúa el usuario; por ejemplo, formularios y vistas web. MDN
    Back-end Lógica del servidor, acceso a datos, seguridad y servicios de la aplicación. MDN
    Full-stack Perfil que trabaja tanto en front-end como en back-end. Wikipedia
    Team Lead Profesional que coordina el trabajo y el desarrollo de las personas del equipo. Team leader
    Tech Lead Referente que guía decisiones técnicas, arquitectura y calidad del código. Software architect
    UX (User Experience) Experiencia global del usuario al utilizar un producto. Wikipedia
    UI (User Interface) Interfaz visual e interactiva mediante la que una persona utiliza el sistema. Wikipedia
    QA (Quality Assurance) Actividades y procesos para prevenir defectos y asegurar la calidad. Wikipedia
    Tester Profesional que diseña, ejecuta y documenta pruebas de software. ISTQB
    DBA Administrador de bases de datos: gestiona disponibilidad, seguridad, copias y rendimiento. Wikipedia
    Especialista en ciberseguridad Profesional que identifica riesgos y protege sistemas, aplicaciones y datos. OWASP
    Junior / Mid / Senior Denominaciones habituales de experiencia y autonomía profesional; no son niveles universales ni roles de Scrum. Desarrollador de software

    Cliente-servidor Arquitectura en la que un cliente solicita servicios a un servidor. Wikipedia

    Base de datos relacional Sistema que organiza datos en tablas relacionadas. Wikipedia
    SQL Lenguaje para consultar y modificar bases de datos relacionales. Wikipedia
    Autenticación Comprobación de la identidad de un usuario. OWASP

    Framework Conjunto estructurado de componentes y convenciones para construir aplicaciones. Wikipedia

    ORM Técnica que relaciona objetos del programa con tablas de una base de datos. Wikipedia
    Microservicios Estilo arquitectónico basado en servicios pequeños desplegables de forma independiente. Wikipedia

    7. Calidad, pruebas y colaboración¶

    Término Significado y ejemplo Ampliación
    Prueba unitaria Verifica una unidad pequeña de código, como un método que calcula una multa. Wikipedia
    Prueba de integración Comprueba que componentes distintos colaboran correctamente. Wikipedia
    Prueba de sistema Comprueba el comportamiento del sistema completo. Wikipedia
    Prueba de aceptación Verifica que la solución satisface las necesidades acordadas. Wikipedia
    Bug Defecto que puede provocar un comportamiento incorrecto. Wikipedia
    Depuración (debugging) Proceso de localizar, comprender y corregir defectos. Wikipedia
    Refactorización Mejora de la estructura interna del código sin cambiar su comportamiento observable. Wikipedia
    Revisión de código Inspección de cambios por otros miembros del equipo antes de integrarlos. GitHub Docs
    Repositorio Espacio donde se almacenan y versionan los archivos y cambios del proyecto. Git
    Rama (branch) Línea de desarrollo que permite trabajar en cambios sin modificar directamente otra rama. Git
    Commit Registro de un conjunto de cambios en el historial del repositorio. Git
    Merge Integración de cambios de distintas ramas. Git
    Pipeline Secuencia automatizada de pasos como compilar, probar y desplegar. GitHub Actions
    Entorno de desarrollo Configuración donde se programa y prueba durante la construcción del software. Wikipedia
    Entorno de producción Infraestructura real donde se ejecuta la aplicación para sus usuarios. Deployment environment

    8. Ejemplo integrado: aplicación de biblioteca¶

    Un equipo quiere desarrollar una aplicación web y Android para buscar libros y gestionar préstamos:

    1. Análisis: el analista entrevista a usuarios y documenta requisitos funcionales y no funcionales.
    2. Producto: el Product Owner ordena el Product Backlog; la búsqueda por título tiene prioridad.
    3. Diseño: UX/UI prepara el prototipo y el Tech Lead propone una arquitectura cliente-servidor.
    4. Sprint Planning: los Developers seleccionan elementos y elaboran un plan para alcanzar el Sprint Goal.
    5. Desarrollo: React construye la web; Kotlin y Compose, la app Android; Spring Boot expone GET /api/libros?titulo=java; PostgreSQL almacena los libros.
    6. Calidad: el equipo incorpora pruebas unitarias y de integración y revisa una pull request.
    7. Integración: GitHub Actions ejecuta las pruebas automáticamente.
    8. Sprint Review: el Scrum Team presenta el incremento a los interesados y recoge comentarios.
    9. Sprint Retrospective: el Scrum Team identifica mejoras en su forma de trabajar.
    10. Mantenimiento: tras el despliegue se corrigen errores y se planifican nuevas funcionalidades.
    flowchart LR
    WEB[Web: React] --> API[API REST: Spring Boot]
    APP[Android: Kotlin y Compose] --> API
    API --> DB[(PostgreSQL)]
    API --> SEG[Autenticación y permisos]

    9. Diferencias que no debes confundir¶

    Conceptos Diferencia esencial
    Scrum / Kanban Scrum organiza el trabajo mediante Sprints, responsabilidades y eventos; Kanban pone el foco en gestionar y mejorar el flujo.
    Ágil / Scrum Ágil es un conjunto de valores y principios; Scrum es un marco concreto.
    Iteración / Incremento Iteración es repetir un ciclo; incremento es añadir un resultado utilizable.
    Product Owner / Project Manager El primero responde por el valor y la gestión del producto en Scrum; el segundo gestiona aspectos generales de un proyecto en organizaciones que utilizan ese puesto.
    Scrum Master / Team Lead El Scrum Master responde por la eficacia del equipo y la aplicación de Scrum; Team Lead es un puesto organizativo de coordinación.
    UX / UI UX estudia la experiencia global; UI diseña los elementos de interacción e interfaz.
    Front-end / Back-end Front-end es la interfaz; back-end es la lógica y servicios que suelen ejecutarse en servidor.
    API / Base de datos La API expone operaciones a otros programas; la base de datos almacena y permite consultar información.
    Autenticación / Autorización Autenticación: quién eres. Autorización: qué puedes hacer.
    CI / Entrega continua / Despliegue continuo CI integra y verifica cambios; entrega continua los deja listos para publicar; despliegue continuo los publica automáticamente.
    QA / Testing QA abarca procesos de calidad; testing es una de las actividades para evaluar el software.
