    Herramientas y asistentes en el desarrollo de aplicaciones (2026)¶

    El desarrollo de software requiere herramientas para analizar requisitos, diseñar interfaces, programar, colaborar, comprobar la calidad, desplegar y mantener las aplicaciones. Ninguna herramienta sustituye por sí sola a un proceso de trabajo bien definido.

    Objetivos de aprendizaje

    • Identificar herramientas según la fase del ciclo de vida.
    • Distinguir un editor, un IDE, un sistema de control de versiones y una plataforma de alojamiento de repositorios.
    • Reconocer las posibilidades y limitaciones de los asistentes de IA.
    • Comprender el flujo básico de integración continua y despliegue.
    • Seleccionar herramientas justificando su utilidad para un proyecto sencillo.

    1. Entornos de desarrollo integrados (IDE) y editores¶

    Un IDE (Integrated Development Environment) reúne herramientas de edición, ejecución, depuración, gestión de proyectos y, habitualmente, integración con compiladores o sistemas de construcción. Un editor de código se centra en la edición y puede ampliarse mediante extensiones hasta ofrecer funciones semejantes a las de un IDE.

    Herramienta Tipo y usos habituales Enlace
    Visual Studio Code Editor extensible para Java, Python, JavaScript y desarrollo web; terminal y depuración mediante extensiones Sitio oficial
    IntelliJ IDEA IDE especialmente utilizado en Java y Kotlin; refactorización, depuración e integración con herramientas de construcción Sitio oficial
    PyCharm IDE orientado a Python Sitio oficial
    WebStorm IDE para JavaScript y TypeScript Sitio oficial
    Android Studio IDE oficial para Android, con emulador, herramientas de Kotlin y Jetpack Compose Sitio oficial
    Visual Studio IDE orientado, entre otros, a C# y .NET Sitio oficial

    Herramientas complementarias: JDK para compilar y ejecutar Java; Gradle o Maven para automatizar la construcción y gestionar dependencias; depuradores para localizar errores.

    Ejemplo en 1.º DAM

    En VS Code se crea un programa Java, se ejecuta y se coloca un breakpoint para observar cómo cambia una variable durante un bucle. El editor facilita el trabajo, pero la ejecución depende de disponer de un JDK configurado.

    Desarrollo en la nube¶

    GitHub Codespaces permite trabajar en entornos de desarrollo alojados en la nube. Replit ofrece un entorno de programación accesible desde el navegador. Su disponibilidad, límites y costes dependen del servicio y del plan contratado.

    2. Control de versiones y repositorios remotos¶

    Git es un sistema de control de versiones distribuido: registra cambios mediante commits y permite trabajar con ramas. GitHub, GitLab y Bitbucket son plataformas que alojan repositorios Git y añaden herramientas de colaboración; no son sinónimos de Git.

    Herramienta Función principal Enlace
    Git Historial local, ramas y fusiones Documentación
    GitHub Repositorios remotos, issues, pull requests y GitHub Actions Documentación
    GitLab Repositorios, merge requests y pipelines CI/CD Documentación
    Bitbucket Repositorios y colaboración, con integración en el ecosistema Atlassian Sitio oficial

    Ejemplo de trabajo colaborativo¶

    git clone https://github.com/organizacion/proyecto.git
cd proyecto
git switch -c feature/formulario
# Editar los archivos del proyecto
git add .
git commit -m "Añade formulario inicial"
git push -u origin feature/formulario

    Después se abre una pull request (en GitHub) para revisar e integrar los cambios. Los comandos presuponen permisos de escritura sobre el repositorio remoto y un sistema de autenticación configurado.

    Buenas prácticas

    No subas contraseñas, claves API, tokens ni ficheros .env con secretos. Utiliza .gitignore para excluir archivos locales apropiados, pero recuerda que añadir un archivo a .gitignore no elimina los secretos que ya se hayan registrado en el historial.

    3. Asistentes de inteligencia artificial¶

    Los asistentes de IA pueden explicar código, proponer pruebas, generar borradores de documentación y sugerir soluciones. Sus respuestas pueden contener errores, vulnerabilidades, dependencias inexistentes o información desactualizada: el desarrollador debe revisar, ejecutar y probar el resultado.

    Asistente Uso habitual Enlace
    GitHub Copilot Asistencia de programación integrada en editores y flujos de desarrollo GitHub Copilot
    ChatGPT Explicación, generación y revisión de código, documentación y análisis de errores ChatGPT
    Gemini Code Assist Asistencia para desarrollo e integración con entornos compatibles Documentación
    Amazon Q Developer Asistencia de desarrollo, especialmente en el ecosistema AWS Sitio oficial
    Tabnine Asistencia de código con opciones de despliegue y privacidad según producto y plan Sitio oficial
    Windsurf Editor y herramientas de desarrollo asistidas por IA; relacionado con la evolución de Codeium Sitio oficial

    Nombres y productos

    Amazon CodeWhisperer pasó a integrarse en Amazon Q Developer. La marca Codeium evolucionó hacia Windsurf. Las funciones y condiciones comerciales de estos servicios cambian con frecuencia: consulta siempre su documentación oficial.

    Uso responsable de la IA¶

    1. Explicar qué problema se quiere resolver, el lenguaje y las restricciones.
    2. Pedir una solución comprensible y verificar las dependencias propuestas.
    3. Revisar el código antes de ejecutarlo y comprobar su seguridad.
    4. Ejecutar pruebas con casos normales, límites y entradas incorrectas.
    5. No compartir datos personales, credenciales ni código confidencial sin autorización.
    6. Respetar las normas de autoría y uso de IA establecidas para la actividad.

    Ejemplo práctico

    Solicita a un asistente que proponga pruebas para un método Java que calcula la media de un array. Comprueba si contempla el array vacío, valores negativos y decimales. No des por correctas las pruebas solo porque las haya generado una IA.

    4. Herramientas colaborativas y gestión de proyectos¶

    Estas herramientas facilitan la planificación, la documentación y la comunicación, pero no determinan por sí mismas si un equipo trabaja con Scrum, Kanban u otro enfoque.

    Categoría Ejemplos Para qué se utilizan
    Seguimiento de trabajo Jira, Trello, Linear Tareas, prioridades y tableros
    Documentación y organización Notion, ClickUp, Confluence Wikis, acuerdos y planificación
    Comunicación Slack, Microsoft Teams, Discord Mensajes, reuniones y avisos
    Diagramas y colaboración visual diagrams.net, Miro Procesos, arquitecturas y lluvia de ideas

    Ejemplo de flujo de trabajo

    1. El Product Owner prioriza necesidades del producto y mantiene el Product Backlog si el equipo utiliza Scrum.
    2. El equipo selecciona y organiza el trabajo conforme a su método de gestión.
    3. Un desarrollador implementa una tarea en una rama de Git.
    4. Otro miembro revisa la pull request y las pruebas automáticas.
    5. El equipo actualiza el tablero y documenta las decisiones.

    En Scrum, el Scrum Master facilita la adopción de Scrum y ayuda a eliminar impedimentos; no es el jefe del equipo ni el responsable de supervisar individualmente las tareas. El Tech Lead suele orientar las decisiones técnicas, aunque su denominación y funciones dependen de la organización.

    5. Automatización, pruebas e integración y despliegue continuos (CI/CD)¶

    • Integración continua (CI): integrar cambios con frecuencia y ejecutar comprobaciones automáticas, como compilación y pruebas.
    • Entrega continua (Continuous Delivery): mantener el software preparado para publicarse; la publicación en producción puede requerir una aprobación manual.
    • Despliegue continuo (Continuous Deployment): publicar automáticamente en producción los cambios que superan las comprobaciones definidas.
    Herramienta Categoría Función
    GitHub Actions Automatización CI/CD Ejecutar workflows tras eventos del repositorio
    GitLab CI/CD Automatización CI/CD Ejecutar pipelines de compilación, pruebas y despliegue
    Jenkins Servidor de automatización Configurar procesos automatizados extensibles
    JUnit Pruebas Crear pruebas automatizadas para Java
    Postman API Enviar solicitudes y organizar pruebas de API
    Docker Contenedores Empaquetar aplicaciones y sus dependencias
    Kubernetes Orquestación Gestionar aplicaciones en contenedores

    Diferencia importante

    Docker y Kubernetes no son sistemas de integración continua. Pueden utilizarse dentro de una solución de CI/CD, pero cumplen funciones diferentes. Tampoco basta con tener GitHub Actions para garantizar la calidad: hay que definir y mantener comprobaciones útiles.

    Ejemplo: GitHub Actions para un proyecto Java con Maven¶

    Archivo .github/workflows/java-ci.yml:

    name: Java CI

on:
  push:
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Obtener repositorio
        uses: actions/checkout@v4
      - name: Configurar Java
        uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'
          cache: maven
      - name: Compilar y ejecutar pruebas
        run: mvn -B verify

    Este ejemplo requiere un proyecto Maven con pom.xml y pruebas configuradas. Las versiones de las acciones deben revisarse en la documentación antes de utilizar el ejemplo en un proyecto real. Si el proyecto usa Gradle, el comando y la configuración deben adaptarse.

    6. Diseño, prototipado y experiencia de usuario (UX/UI)¶

    • UX (User Experience): estudia las necesidades, la facilidad de uso y la experiencia global de la persona usuaria.
    • UI (User Interface): define los componentes visuales y la presentación de la interfaz.
    • Wireframe: esquema inicial de distribución de contenidos y controles.
    • Prototipo: representación que permite explorar o simular interacciones antes de implementar el producto.
    Herramienta Utilidad Enlace
    Figma Diseño de interfaces y prototipado colaborativo Figma
    Penpot Diseño y prototipado colaborativo con enfoque de código abierto Penpot
    Canva Bocetos, presentaciones y materiales visuales; no sustituye todas las funciones de un editor UX/UI Canva
    Miro Diagramas, recorridos de usuario y colaboración visual Miro

    Adobe XD se mantiene como producto heredado en modo mantenimiento; no se recomienda presentarlo como herramienta principal para proyectos nuevos.

    Relación entre diseño, desarrollo y mejora continua¶

    flowchart TD
    A["Diseño UX/UI"]

    D["Despliegue"]
    E["Feedback de usuarios"]

    A --> B
    B --> C
    C --> D
    D --> E

    Interpretación del diagrama

    Es un esquema simplificado: en proyectos reales el diseño, las pruebas y el feedback pueden producirse de forma paralela y repetirse durante todo el ciclo. Las pruebas automatizadas no sustituyen todas las pruebas manuales o de usabilidad.

    7. Relación entre herramientas y fases del desarrollo¶

    Fase Herramientas posibles Resultado esperado
    Análisis de requisitos Jira, Trello, Notion, Miro Requisitos y prioridades documentados
    Diseño Figma, Penpot, diagrams.net Wireframes, prototipos y diagramas
    Implementación VS Code, IntelliJ IDEA, Android Studio, Git Código y cambios versionados
    Pruebas JUnit, Postman, GitHub Actions Evidencias de comprobación y errores detectados
    Despliegue GitHub Actions, Docker, servicios de alojamiento Versión publicada y verificable
    Mantenimiento GitHub Issues, sistemas de registro y seguimiento Correcciones y mejoras planificadas

    Una herramienta puede utilizarse en varias fases; la elección depende de los requisitos, el equipo, la infraestructura y el presupuesto.

    8. Actividad práctica: PR 307 — EduTrack¶

    PR 307 (RA1 / CE1b, CE1f, CE1g / IC2 / 5p). Los códigos de evaluación se conservan del documento original y deben contrastarse con la programación didáctica del módulo.

    Situación de partida¶

    Formas parte de un pequeño equipo de desarrollo de EduTrack, una startup educativa que quiere crear aplicaciones sencillas para facilitar el aprendizaje digital. El equipo debe idear una aplicación, explicar su utilidad y construir una primera versión funcional mínima (MVP) en dos sesiones.

    El objetivo no es desarrollar una aplicación completa, sino recorrer a pequeña escala el proceso: idea → análisis → diseño → implementación → pruebas → demostración → feedback.

    Sesión 1. Análisis y diseño¶

    1. Elegid un problema educativo concreto y describid a sus usuarios.
    2. Redactad al menos tres requisitos funcionales y uno no funcional.
    3. Priorizad los requisitos e identificad la funcionalidad mínima que vais a implementar.
    4. Dibujad un wireframe o prototipo de la pantalla principal.
    5. Organizad las tareas en un tablero y cread un repositorio Git.

    Sesión 2. Implementación y validación¶

    1. Implementad una funcionalidad mínima ejecutable con las tecnologías conocidas por el equipo.
    2. Registrad al menos dos commits descriptivos.
    3. Preparad y ejecutad tres casos de prueba, anotando el resultado esperado y el obtenido.
    4. Demostrad la aplicación y recoged una propuesta de mejora.
    5. Explicad qué herramientas habéis utilizado y por qué.

    Ejemplo de MVP

    Una aplicación de tarjetas de estudio permite introducir una pregunta y su respuesta y mostrarlas en pantalla. En esta primera versión no es necesario implementar autenticación, base de datos ni sincronización en la nube.

    Entregables¶

    • Documento breve con problema, usuarios y requisitos.
    • Wireframe o prototipo.
    • Enlace al repositorio y evidencia de los commits.
    • Código ejecutable o demostración reproducible.
    • Tabla con tres pruebas y sus resultados.
    • Reflexión final sobre herramientas, dificultades y mejoras.

    Criterios orientativos de valoración (5 puntos)¶

    Aspecto Puntuación
    Definición del problema y requisitos 1,0
    Diseño y organización del trabajo 1,0
    Implementación funcional mínima 1,5
    Pruebas y evidencias 1,0
    Justificación de herramientas y reflexión 0,5
    Total 5,0

    Recomendación didáctica

    Seleccionad pocas herramientas y utilizadlas correctamente. Para esta práctica pueden bastar VS Code o IntelliJ IDEA, Git, GitHub y diagrams.net. La IA es opcional y su uso debe declararse si así lo exige el docente.
